# pxw3pev2.0

PX-W3PE V2.0 を Linux で動かすための、Rust 製カーネルドライバです。  
カードを挿して `modprobe pxw3pe` すると `/dev/dvb/adapter0`〜`adapter3` が生え、普通の DVB デバイスとして使えます。

## 特徴

- **DVB アダプタ ×4**: ISDB-S が 0 と 1、ISDB-T が 2 と 3。4 ストリームが 1 つの DMA ポートに相乗りして届くため、ドライバがタグを見て仕分けします。mirakc でも recisdb でも普通に使えます。
- **15 V LNB 給電**: 冷起動直後はなぜか給電ビットが立っているため、初期化でまず切ります。以後は `FE_SET_VOLTAGE` で入り、誰も使わなくなったら切れ、短絡時は保護で遮断されます。
- **基板上の B-CAS リーダー**: `/dev/pxw3pe-cardN` として見え、T=1 はドライバ自身が処理します。pcscd 用のハンドラは `tools/ifd-pxw3pe/` にあります。
- **誤バインド防止**: 同じブリッジを使う他カードとは裏の回路が違うため、サブシステム ID `0b06:0003` 以外はお断りします。

## 実機で確認したこと

Linux 6.18.59（x86-64）の実機にて：

- 4 チューナー同時に地上波と BS を受信（合計約 72 Mbit/s）。PAT の CRC はすべて一致し、同期落ちありません。
- LNB 給電で BS アンテナを駆動し、BS-21 まで受信できることを確認。
- モジュールのアンロードと再読み込みは、再起動なしで何度でも可能です。

## まだのこと

- **サスペンド**: Linux kernelがサスペンド未対応のため未対応。スリープ中にチップが設定を忘れるため、休止前にモジュールを外してください。

## 動かし方

### 1. カーネルの準備
`CONFIG_RUST` と `CONFIG_DVB_CORE` が有効なカーネルが必要です。ディストリビューションのカーネルは Rust が無効なことが多いため、付属のスクリプトでビルドできます：

```sh
sudo -i
kernel/build-kernel.sh 6.18.59
```

### 2. ドライバのインストール（DKMS）
カーネルのビルド鍵で署名する設定を入れてからインストールします。

```sh
sudo -i
install -D -m 0644 kernel/dkms-kernel-key.conf /etc/dkms/framework.conf.d/kernel-key.conf
mkdir -p /usr/src/pxw3pe-0.1.0
cp -r driver/* /usr/src/pxw3pe-0.1.0/
dkms add pxw3pe/0.1.0
dkms install pxw3pe/0.1.0 -k $(uname -r)
modprobe pxw3pe
```

チューニングは通常の DVB API です。ISDB-S は `DTV_FREQUENCY` に IF（kHz）、`DTV_STREAM_ID` に TSID を渡します。

### 3. カードリーダー（任意）
```sh
cd tools/ifd-pxw3pe && cargo build --release
sudo install -D -m 0644 target/release/libifd_pxw3pe.so /usr/local/lib/pcsc/drivers/serial/libifd_pxw3pe.so
sudo install -D -m 0644 packaging/pxw3pe /etc/reader.conf.d/pxw3pe
sudo systemctl restart pcscd.service
```

## 基板の構成とデータの流れ

アンテナからユーザー空間まで、TS は次の順に流れます。

```
 BS アンテナ (LNB 15 V は ASIE5606 で入切)             地上波アンテナ
      |                                                      |
  TDA20142 --ループスルー--> TDA20142                 分配器 (推定)
      |                          |                      /         \
      |                          |                NM120          NM120
      v                          v                  v              v
+---------------------- TC90522 (4 コアの復調器 1 個) -----------------------+
|  0x11 ISDB-S                 0x13 ISDB-S      0x10 ISDB-T  0x12 ISDB-T     |
|  各コアで復調と誤り訂正 -> 4 本の TS を 1 本の出力にまとめ、               |
|  各パケットにコア別のタグを付ける                                          |
+--------------------------------------+-------------------------------------+
                                       v
                    ASIE5606: 全パケットに XOR スクランブル
                                       v
                   ASV5220 (PCIe ブリッジ) の TS 入力ポート B
             入力段 -> DMA (ピンポン 2 チャネル) -> ホストのメモリ
                                       v
    ドライバ: タグで 4 チューナーに振り分け -> 先頭を 0x47 に戻す
              -> XOR を解除 -> DVB demux -> /dev/dvb/adapterN/dvr0
                                       v
                           mirakc などのアプリケーション
```

**チューナー**  
衛星は TDA20142 が 2 個で、直列につながっています。アンテナを受けるのはコア 0x11 側の 1 個目で、2 個目（0x13 側）にはそのループスルー出力から信号が渡ります。1 個目のループスルーを切ると 2 個目の C/N が大きく落ちます。地上波は NM120 が 2 個で、こちらはループスルーを持たず、アンテナ入力を分けて並列に受けています（分配器は推定）。どのチューナーも I2C に直接はつながっておらず、担当する復調器コアの中継レジスタ（0xFE）越しに操作します。

**復調器**  
東芝 TC90522 が 1 個で、中に ISDB-S と ISDB-T のコアが 2 つずつ入っています（I2C アドレス 0x10〜0x13）。復調と誤り訂正はコアごとに行われます。受信が乱れたときに見えるのはパケットの欠けで、TEI の立ったパケットはこれまでの記録は流れません。4 コアの TS は 1 本の出力にまとめられ、各パケットの先頭バイト（同期バイト 0x47）の上位 2 ビットが、コアごとに決まった値に置き換えられます。こうしてできたタグが 0x47 / 0xC7 / 0x87 / 0x07 です。同期バイトは常に同じ値なので、ここに番号を入れてもデータは失われません。タグを付けるのは復調器です。ブリッジの入力ポートは 4 コア分をまとめた 1 本の TS しか受けず、パケットがどのコアから来たかを知る手段がありません。衛星コアが起動し直す瞬間にまれに出す 1 パケットは、タグのないまま届きます（集めた 6 個のうち 5 個は、エネルギー拡散用の擬似乱数列に一定のバイトを XOR しただけの中身で、受信データが届く前に復調器の中で作られたパケットです）。ドライバはタグのないパケットを捨てます。

**ASIE5606（制御チップ）**  
復調器とブリッジのあいだに位置し、全パケットに XOR スクランブルをかけます。シードを書かないうちは TS を通しません。LNB 給電の入切と復調器のリセット線もこのチップの担当です。

**ASV5220（PCIe ブリッジ）**  
TS を受けて DMA でホストのメモリに書き込み、完了と入力あふれを割り込みで知らせます。ほかのチップを操作する I2C マスター、電源とリセットの GPIO、B-CAS リーダー用の UART もここにあります。

**NULL パケット**  
NULL パケット（PID 0x1FFF）は DMA まで届きません。落としているのは復調器だと考えています。ブリッジの入力段は受け取って捨てたパケットを ERR カウンタに数えますが、 NULL パケットはそこに現れないので、ブリッジまで来ていません（入力段より手前にブリッジの別の仕組みがある可能性は残ります）。ブリッジの制御ビットや、復調器の TS 出力まわりのレジスタを 1 ビットずつ反転しても、NULL パケットが出てくることはありません。
